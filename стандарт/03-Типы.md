# Типы

\# У каждого реквизита есть тип. Объект спецификации — тоже тип: документ объекта определяет его, а другие документы ссылаются на него.

## Виды типов

| Вид | Как записывается | Где определяется |
|---|---|---|
| Базовый | `Строка`, `Число(10)`, `Булево`, `Дата` | [Базовые типы](#Базовые%20типы) |
| Объект | `Ссылка."Заказ"` | Документ объекта |
| Перечисление | `Ссылка."СтатусЗаказа"` | Раздел «Типы и перечисления» документа объекта ([Определение типа](#Определение%20типа)) |
| Вложенный | `Ссылка."ПозицияЗаказа"` | Раздел «Типы и перечисления» документа объекта-хозяина ([Определение типа](#Определение%20типа)) |
| Список | `Список.ТипЭлемента`: `Список.Ссылка."ПозицияЗаказа"` | Тип элемента — по своему виду |
| Необязательный | Суффикс `?` у любого типа: `Дата?`; у ссылки — внутри текста ссылки: `[Ссылка."Покупатель"?](Покупатель.md)` | Без `?` значение обязательно |
| Со значением по умолчанию | После типа — `= значение`: `Ссылка."СтатусЗаказа" = Новый` | Значение из языка выражений ([Методы: Язык выражений](04-Методы.md#Язык%20выражений)) |

| Правило | Как выполнять | Проверка |
|---|---|---|
| ВидТипа | Тип реквизита записан одним из видов таблицы выше; базовый тип — только из таблицы [Базовые типы](#Базовые%20типы). `Число` без размерности — ошибка; `Структура` — ошибка, состав задаётся вложенным типом ([Определение типа](#Определение%20типа)) | Генератор |
| ЗначенияВТестах | Значение реквизита в сгенерированном тесте берётся из типа: значение по умолчанию, иначе для обязательного — пустая строка с именем реквизита, ноль, `Ложь`, дата теста, пустой список, первое значение перечисления или объект со значениями по умолчанию; для необязательного — `null`. Условия метода добавляют к перебору свои константы и соседние с ними числа ([Методы: Таблица решений](04-Методы.md#Таблица%20решений)) | Тесты |

## Базовые типы

| Тип | Смысл |
|---|---|
| `Строка`, `Строка(Длина)` | Текст; без длины — неограниченный |
| `Число(Длина,Точность)` | Число: Длина — всего цифр, Точность — цифр после запятой, нулевую можно не писать. `Число(10)` — целое до 10 цифр, `Число(15,2)` — сумма с копейками |
| `Число(Длина,Точность,Неотрицательное)` | То же, только не меньше нуля; генератор не подставляет отрицательных значений |
| Булево | Истина или ложь |
| Дата | Дата и время |

## Реквизиты

\# Пример объекта «Заказ»:

| Имя | Описание | Тип |
|---|---|---|
| Покупатель | Кто оформил заказ | [Ссылка."Покупатель"](Покупатель.md) |
| Статус | Стадия заказа | [Ссылка."СтатусЗаказа"](#СтатусЗаказа) = Новый |
| Сумма | Сумма к оплате в рублях | Число(15,2,Неотрицательное) |
| ДатаОплаты | Когда заказ оплачен; пусто до оплаты | Дата? |

| Правило | Как выполнять | Проверка |
|---|---|---|
| ФорматРеквизитов | Ровно три колонки: `Имя`, `Описание`, `Тип`; ссылки — только в колонке `Тип` | Генератор |
| СсылкаНаТип | Ссылка в колонке `Тип` ведёт на документ объекта, на заголовок перечисления или на заголовок вложенного типа этого же документа | Генератор |
| Инвариант | Постоянное условие на реквизиты — строка таблицы `Правило`, `Условие` под таблицей реквизитов, условие по правилу [ПростоеУсловие](04-Методы.md#Таблица%20решений). Генератор проверяет, что ни одна строка ни одного метода его не нарушает, и падает с именем правила; раз тесты сравнивают состояние кода с состоянием спецификации, в коде инвариант тоже держится | Генератор |
| ТестРеквизитов | Генератор порождает тест: объект создаётся ровно с этими реквизитами и читается с теми же значениями | Тесты |

## Определение типа

\# Перечисление и вложенный тип определяются в разделе «Типы и перечисления» документа объекта.

| Правило | Как выполнять | Проверка |
|---|---|---|
| ОдноОпределение | Каждый тип определён в одном документе: заголовок определения типа уникален во всей спецификации, остальные документы ссылаются на него. Данные, которые уже описаны в другом объекте, подключаются ссылкой на этот объект, а не копией части его реквизитов; генератор проверяет только совпадение имён | Генератор |
| СвойДокумент | Свой документ — у того, что используется без хозяина: его показывают, ищут или считают отдельно. Часть, которая без хозяина смысла не имеет, — вложенный тип в документе хозяина, даже если хранится в своей таблице. На вложенный тип ссылается только документ хозяина | Нет |
| Заголовок | Заголовок раздела — имя типа, затем комментарий с назначением | Генератор |
| Перечисление | Таблица `Имя`, `Описание`, за ними при необходимости колонки свойств значения. В заголовке колонки свойства — имя и тип, как в колонке `Тип` реквизитов: `Баллы: Число(3)`; значения колонки подходят под этот тип. Свойство с именем `Тип` запрещено | Генератор |
| Вложенный | Таблица в формате раздела [Реквизиты](#Реквизиты) | Генератор |
| ТестПеречисления | Генератор порождает тест: в коде ровно эти значения, в том же порядке | Тесты |

### СтатусЗаказа

\# Пример перечисления: стадии заказа.

| Имя | Описание |
|---|---|
| Новый | Заказ оформлен, не оплачен |
| Оплачен | Оплата получена |
| Отменён | Заказ отменён до оплаты |
