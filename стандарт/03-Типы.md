# Типы

\# У каждого реквизита есть тип. Объект спецификации — тоже тип: документ объекта определяет его, а другие документы ссылаются на него.

## Виды типов

| Вид | Как записывается | Где определяется |
|---|---|---|
| Базовый | `Строка`, `Число(10)`, `Булево`, `Дата` | [Базовые типы](#Базовые%20типы) |
| Объект | `Ссылка."Заказ"` | Документ объекта |
| Перечисление | `Ссылка."СтатусЗаказа"` | Раздел «Типы и перечисления» документа объекта ([Определение типа](#Определение%20типа)) |
| Вложенный | `Ссылка."ПозицияЗаказа"` | Раздел «Типы и перечисления» документа объекта-хозяина ([Определение типа](#Определение%20типа)) |
| Список | `Список.ТипЭлемента`: `Список.Ссылка."ПозицияЗаказа"` | Тип элемента — по своему виду |
| Необязательный | Суффикс `?` у любого типа: `Дата?`; у ссылки — внутри текста ссылки: `[Ссылка."Покупатель"?](Покупатель.md)` | Без `?` значение обязательно |
| Со значением по умолчанию | После типа — `= значение`: `Ссылка."СтатусЗаказа" = Новый` | Значение из языка выражений ([Методы: Язык выражений](04-Методы.md#Язык%20выражений)) |

| Правило | Как выполнять | Проверка |
|---|---|---|
| ВидТипа | Тип реквизита записан одним из видов таблицы выше; базовый тип — только из таблицы [Базовые типы](#Базовые%20типы). `Число` без размерности — ошибка; `Структура` — ошибка, состав задаётся вложенным типом ([Определение типа](#Определение%20типа)) | Генератор |
| ЗначенияВТестах | Значение реквизита в сгенерированном тесте берётся из типа: значение по умолчанию, иначе для обязательного — пустая строка с именем реквизита, ноль, `Ложь`, дата теста, пустой список, первое значение перечисления или объект со значениями по умолчанию; для необязательного — `null`. Если такое число нарушает [ограничение](#Ограничения%20и%20инварианты), берётся ближайшее к нулю, которое не нарушает; другое значение — ошибка генерации, его задают после `=`. Условия метода добавляют к перебору свои константы и соседние с ними числа ([Методы: Таблица решений](04-Методы.md#Таблица%20решений)); состояния, где нарушено ограничение или инвариант, в перебор не попадают | Тесты |

## Базовые типы

| Тип | Смысл |
|---|---|
| `Строка`, `Строка(Длина)` | Текст; без длины — неограниченный |
| `Число(Длина,Точность)` | Число: Длина — всего цифр, Точность — цифр после запятой, нулевую можно не писать. `Число(10)` — целое до 10 цифр, `Число(15,2)` — сумма с копейками |
| Булево | Истина или ложь |
| Дата | Дата и время |

## Реквизиты

\# Пример объекта «Заказ»:

| Имя | Описание | Тип | Ограничение |
|---|---|---|---|
| Покупатель | Кто оформил заказ | [Ссылка."Покупатель"](Покупатель.md) | — |
| Статус | Стадия заказа | [Ссылка."СтатусЗаказа"](#СтатусЗаказа) = Новый | — |
| Сумма | Сумма к оплате в рублях | Число(15,2) | ≥ 0 |
| Оплачено | Сколько оплачено | Число(15,2) | ≥ 0 |
| Долг | Сколько осталось оплатить | Число(15,2) | ≥ 0 «Оплата больше долга» |
| Комментарий | Пожелание покупателя | Строка(500) | Длина ≤ 300 «Не больше 300 символов»; ≠ «—» |
| ДатаОплаты | Когда заказ оплачен; пусто до оплаты | Дата? | — |

\# Его подраздел «Инварианты»:

| Правило | Условие | Ошибка |
|---|---|---|
| СуммаСходится | Оплачено + Долг = Сумма | — |
| ДатаТолькоУОплаченного | ДатаОплаты = null или Статус = Оплачен | «Дата оплаты только у оплаченного заказа» |

| Правило | Как выполнять | Проверка |
|---|---|---|
| ФорматРеквизитов | Ровно четыре колонки: `Имя`, `Описание`, `Тип`, `Ограничение`; ссылки — только в колонке `Тип` | Генератор |
| СсылкаНаТип | Ссылка в колонке `Тип` ведёт на документ объекта, на заголовок перечисления или на заголовок вложенного типа этого же документа | Генератор |
| ТестРеквизитов | Генератор порождает тест: объект создаётся ровно с этими реквизитами и читается с теми же значениями | Тесты |

## Ограничения и инварианты

\# Тип говорит, как значение хранится: длина строки, цифры числа, обязательность. Какие значения допустимы, говорят ограничение одного реквизита и инвариант на несколько реквизитов.

| Вид | Пример | Где записан |
|---|---|---|
| Ограничение | `≥ 0`, `Длина ≥ 1`, `∈ [Новый, Оплачен]` | Колонка `Ограничение` таблицы реквизитов |
| Инвариант | `Оплачено + Долг = Сумма` | Подраздел «Инварианты» |

| Правило | Как выполнять | Проверка |
|---|---|---|
| Ограничение | Условие на один реквизит языком выражений ([Методы: Язык выражений](04-Методы.md#Язык%20выражений)); имя реквизита не пишется, условие начинается со сравнения (`≥ 18`, `∈ [А, Б]`) или с `Длина` (`Длина ≥ 1` — длина строки или списка). Несколько условий — через `;`, выполняются все. `—` — ограничений нет. Другой реквизит в ограничении — ошибка: это инвариант. У необязательного реквизита ограничение проверяется, когда значение есть | Генератор |
| ТекстОграничения | После условия — свой текст ошибки в «»: `≥ 18 «Только для взрослых»; ≤ 120 «Проверьте возраст»`. Без текста ошибка называет реквизит и условие: `Ошибка «Возраст: ≥ 18»` | Генератор |
| Инвариант | Условие на несколько реквизитов объекта — строка таблицы `Правило \| Условие \| Ошибка` в подразделе «Инварианты» раздела «Реквизиты и инварианты» ([Документ объекта: Элементы документа объекта](02-Документ-объекта.md#Элементы%20документа%20объекта)), условие по правилу [ПростоеУсловие](04-Методы.md#Таблица%20решений). В `Ошибка` — текст в «» или `—`: тогда текст ошибки — имя правила | Генератор |
| КогдаВерны | Ограничения и инварианты верны после создания объекта и после каждого его метода. Внутри метода они могут нарушаться: при переносе суммы между двумя реквизитами инвариант временно ложен. Вызов своего метода из действий (`Закрыть()`) — часть внешнего метода; метод другого объекта охраняет свой объект | Нет |
| Охрана | Метод, после которого нарушено ограничение или инвариант, отвечает `Ошибка «текст»` этого правила, реквизиты объекта остаются прежними. Охранную строку в метод писать не нужно. Если она есть (`Переплата \| Сколько > Долг \| — \| Ошибка «…»`), она срабатывает раньше и даёт свой текст. Уже сделанные вызовы внешних объектов не отменяются: чтобы письмо не ушло, охранная строка нужна перед вызовом | Тесты |
| ТестОхраны | Для каждого метода, который меняет реквизит из ограничения или условия инварианта, генератор ищет по всему перебору вход, на котором после метода правило нарушилось бы, и порождает тест: ожидается `Ошибка «текст»` и неизменные реквизиты ([Тесты по спецификации](05-Тесты-по-спецификации.md#Что%20порождается)). Если такого входа нет, теста нет: метод правило не нарушает | Генератор |
| ИзменениеРеквизита | Реквизит меняется только действием метода своего объекта; вложенная часть — только методом хозяина. Так ограничение и инвариант охраняет один объект | Нет |
| ОграничениеПараметра | У параметра метода колонки `Ограничение` нет: недопустимое значение отсекает строка метода с `Ошибка «текст»` ([Методы: Таблица решений](04-Методы.md#Таблица%20решений)) | Нет |

## Определение типа

\# Перечисление и вложенный тип определяются подразделами «Перечисление» и «Вложенный тип» в разделе «Типы и перечисления» документа объекта.

| Правило | Как выполнять | Проверка |
|---|---|---|
| ОдноОпределение | Каждый тип определён в одном документе: заголовок определения типа уникален во всей спецификации, остальные документы ссылаются на него. Данные, которые уже описаны в другом объекте, подключаются ссылкой на этот объект, а не копией части его реквизитов; генератор проверяет только совпадение имён | Генератор |
| СвойДокумент | Свой документ — у того, что используется без хозяина: его показывают, ищут или считают отдельно. Часть, которая без хозяина смысла не имеет, — вложенный тип в документе хозяина, даже если хранится в своей таблице. На вложенный тип ссылается только документ хозяина | Нет |
| Заголовок | Заголовок подраздела — имя типа, затем комментарий с назначением | Генератор |
| Перечисление | Таблица `Имя`, `Описание`, за ними при необходимости колонки свойств значения. В заголовке колонки свойства — имя и тип, как в колонке `Тип` реквизитов: `Баллы: Число(3)`; значения колонки подходят под этот тип. Свойство с именем `Тип` запрещено | Генератор |
| Вложенный | Пункт «Реквизиты» с таблицей в формате раздела [Реквизиты](#Реквизиты), с колонкой `Ограничение`; за ним, если есть инварианты, пункт «Инварианты». Их охраняет метод хозяина, который меняет вложенную часть | Генератор |
| ТестПеречисления | Генератор порождает тест: в коде ровно эти значения, в том же порядке | Тесты |

### СтатусЗаказа

\# Пример перечисления: стадии заказа.

| Имя | Описание |
|---|---|
| Новый | Заказ оформлен, не оплачен |
| Оплачен | Оплата получена |
| Отменён | Заказ отменён до оплаты |
