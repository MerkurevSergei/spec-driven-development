# Методы

\# Метод — поведение объекта. Он записывается таблицей решений, если выбирается один исход, или таблицей шагов, если выполняется последовательность действий. Внутренний алгоритм не описывается: только то, что видно снаружи. По каждой строке таблицы генератор порождает тест ([Тесты по спецификации](05-Тесты-по-спецификации.md)).

## Заголовок метода

| Правило | Как выполнять | Проверка |
|---|---|---|
| ЗаголовокМетода | Заголовок подраздела «Метод» — имя, параметры с типами в скобках и тип ответа после двоеточия: `Оплатить()`, `Отменить(Причина: Строка(200))`, `Факториал(N: Число(3)): Число(10)`. Скобки есть и без параметров; тип ответа есть только у метода с ответом. Тип записывается как в колонке `Тип` реквизитов ([Типы: Виды типов](03-Типы.md#Виды%20типов)) | Генератор |

## Таблица решений

| Правило        | Как выполнять                                                                                              | Проверка |
| -------------- | ---------------------------------------------------------------------------------------------------------- | --- |
| КолонкиРешений | `Правило`, `Условие`, `Действия`, `Ответ`                                                                     | Генератор |
| ПорядокРешений | Строки проверяются сверху вниз; выполняется первая с истинным условием                                     | Тесты |
| ОтветВсегда     | Последняя строка метода — без условия (`—`), чтобы ответ был всегда                                         | Генератор |
| Ответ           | Ответ — значение на языке выражений, `Ошибка «текст»` или `—`, если метод ничего не возвращает. Строка выполняется слева направо: сначала Действия, затем Ответ. Если вызванный метод ответил `Ошибка`, строка на этом прерывается и метод отвечает той же ошибкой; уже выполненные действия остаются. После метода проверяются ограничения и инварианты объекта ([Типы: Ограничения и инварианты](03-Типы.md#Ограничения%20и%20инварианты))             | Генератор |
| ПростоеУсловие | В условии — реквизиты, параметры, реквизиты через ссылку, литералы, сравнения, `∈`, `Длина(…)` и логика. Вызовы методов, `Отбор` и `Последние` — только в действиях и ответах. Так генератор может подобрать состояние, в котором строка срабатывает; для произвольного условия это невозможно | Генератор |

## Таблица шагов

| Правило | Как выполнять | Проверка |
|---|---|---|
| КолонкиШагов | `Правило`, `Шаг`, `Условие`, `Действия`, `Компенсация` | Генератор |
| ПорядокШагов | Шаги выполняются по порядку номеров. Условие шага проверяется перед ним, после действий предыдущих шагов; шаг с ложным условием пропускается. Условие — по правилу `ПростоеУсловие`. Если не подобрать вход, при котором шаг с условием пропускается, генерация падает с указанием шага: условие лишнее или нужна таблица примеров | Тесты |
| Компенсация | Как отменить этот шаг, если упадёт один из следующих: действия на языке выражений или `—`, если отменять нечего. Реквизиты возвращает `Реквизит := Прежнее(Реквизит)`; вызовы внешних объектов не отменяются сами, их компенсируют действиями, например письмом «Заказ отменён». Шаг, на котором сбой, считается невыполненным; компенсации выполненных шагов идут в обратном порядке, затем метод передаёт сбой дальше. У последнего шага компенсации нет. Генератор порождает тест со сбоем на каждом шаге, перед которым есть шаг с компенсацией | Тесты |

## Примеры

\# Если состояние для строки правила перебором не подобрать (например, нужен список из десяти позиций с конкретными суммами), под таблицей метода добавляется таблица примеров.

| Правило | Как выполнять | Проверка |
|---|---|---|
| КолонкиПримеров | `Правило`, `Реквизиты`, `Параметры`. `Правило` — имя строки метода; `Реквизиты` — значение вложенного типа `{Реквизит: значение, …}` поверх значений по умолчанию или `—`; `Параметры` — так же для параметров метода | Генератор |
| ВходБезОтвета | Пример задаёт только вход. Ожидаемый результат генератор вычисляет по спецификации, поэтому пример нельзя подогнать под код | Тесты |
| ПримерВместоПеребора | Строка, для которой генератор не подобрал состояние, обязана иметь пример; иначе генерация падает с указанием строки | Генератор |

## Специальные методы

\# Методы, которые вызывает сама программа в определённый момент.

| Имя | Когда вызывает программа | Для чего |
|---|---|---|
| ПриСоздании() | Объект создан, до первого сохранения | Начальные значения сложнее, чем `= значение` в типе |
| ПередУдалением() | Перед удалением объекта | Отменить связанную работу или запретить удаление (`Ошибка «текст»`) |
| ПриОбновлении() | Для каждого хранимого объекта при первом запуске новой версии, до `ПриЗапуске()` | Перенос данных при переименовании, удалении или смене типа реквизита |
| ПриЗапуске() | Для каждого хранимого объекта при запуске программы, до первого запроса | Привести объект в порядок после перезапуска |

| Правило | Как выполнять | Проверка |
|---|---|---|
| СпециальныйМетод | Метод с именем из таблицы выше вызывает программа в указанный момент; другие методы его не вызывают, параметров у него нет. Описывается в разделе «Методы» таблицей решений или шагов, как обычный метод | Нет |
| ИменаСпециальных | Имя метода на «При» или «Перед» — только из таблицы выше | Нет |

## Язык выражений

\# Один язык для условий, действий и ответов. Генератор исполняет его, чтобы вычислить ожидаемый результат, поэтому каждая ячейка записывается только обозначениями этой таблицы.

| Обозначение | Смысл |
|---|---|
| `Реквизит` | Значение своего реквизита: `Статус` |
| `Реквизит.Реквизит` | Реквизит через ссылку или вложенный тип: `Покупатель.Баллы`; через пустую ссылку — `null` |
| `Параметр` | Параметр метода по имени из заголовка: `Причина` в `Отменить(Причина: Строка(200))`. Имя параметра не совпадает с именем реквизита |
| `=`, `≠`, `<`, `>`, `≤`, `≥`, `∈`, `∉`, `null`, `и`, `или`, `не` | Сравнения и логика; `∈` и `∉` — есть и нет в списке |
| `+`, `-`, `*`, `/` | Арифметика; `+` у списков — добавление элемента или списка |
| `Реквизит := значение` | Действие: присвоить значение |
| `;` | Разделитель нескольких действий |
| `Метод(параметры)` | Вызов другого метода того же объекта; в ответе — и этого же метода (рекурсия) |
| `Реквизит.Метод(параметры)` | Вызов метода объекта по ссылке; у внешнего объекта ([Документ объекта: Внешний объект](02-Документ-объекта.md#Внешний%20объект)) тест проверяет сам вызов и его параметры |
| `{Реквизит: значение}` | Значение вложенного типа или объекта |
| `[]`, `[1, 2]` | Список; `Список + элемент` и `Список + Список` добавляют элементы |
| `Длина(Список)` | Число элементов; у строки — число символов |
| `Первый(Список)` | Первый элемент; у пустого списка — `null` |
| `КромеПервого(Список)` | Список без первого элемента |
| `Последние(Список, N)` | Последние N элементов списка |
| `Прежнее(Реквизит)` | Значение реквизита перед этим шагом; только в колонке `Компенсация` |
| `Отбор(Список, условие)` | Элементы списка, для которых условие истинно; элемент в условии — `Э`: `Отбор(Позиции, Э.Сумма > 100)` |
| `Для каждого Э из Список: действия` | Действие: выполнить действия для каждого элемента; `Э` — элемент; действия идут до конца ячейки |
| `—` | Нет условия, действия или ответа |
| Значение перечисления | Имя из таблицы перечисления: `Статус = Оплачен` |
| `Сейчас` | Текущие дата и время; в тестах подменяются тестовой обвязкой |
| `Ошибка «текст»` | Ответ: отказ с текстом для пользователя |

| Правило   | Как выполнять                                                                                                    | Проверка |
| --------- | ---------------------------------------------------------------------------------------------------------------- | --- |
| Выражение | Каждая ячейка условий, действий и ответов записана обозначениями таблицы выше; неизвестный реквизит, параметр или значение — ошибка | Генератор |
| Завершение | Правило выполняется интерпретатором не больше заданного числа шагов и вложенных вызовов; иначе генерация падает с текстом «правило не завершается». Это защита от зацикленной спецификации, а не ограничение языка: рекурсия, условие и арифметика позволяют записать любой алгоритм | Генератор |

## Грамматика

\# Что нужно знать, чтобы ячейка читалась однозначно.

| Что | Как записывается |
|---|---|
| Число | `10`, `10.5`; разделитель дробной части — точка, запятая разделяет параметры |
| Строка | `«текст»` |
| Булево | `Истина`, `Ложь` |
| Дата | `Дата«2026-10-17 15:00»` |
| Приоритет | Сначала `.`, затем `*` и `/`, затем `+` и `-`, затем сравнения, затем `и`, последним `или`. Скобки меняют порядок. `не` ставится перед значением да/нет или перед скобками: `не Срочная`, `не (А или Б)`. Перед сравнением `не` — ошибка, вместо него пишут `≠` или `∉`: `Статус ≠ Отгружен`, `Статус ∉ [Отгружен, Отменён]` |
| Имя в выражении | Сначала ищется локальное имя (`Э`), затем параметр, затем реквизит, затем значение перечисления |

## Пример

\# Метод «Оплатить» объекта «Заказ».

| Правило | Условие | Действия | Ответ |
|---|---|---|---|
| ОплатаОплаченного | Статус = Оплачен | — | Ошибка «Заказ уже оплачен» |
| Оплата | — | Статус := Оплачен; ДатаОплаты := Сейчас | — |

\# Генератор породит два теста: для заказа со статусом `Оплачен` — отказ с текстом «Заказ уже оплачен» и неизменные реквизиты; для заказа с другим статусом — статус `Оплачен` и дата оплаты, равная подменённому `Сейчас`.
