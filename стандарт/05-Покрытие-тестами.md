# Покрытие тестами

\# Каждое правило спецификации связано с тестом, и эту связь в обе стороны проверяет парсер.

## Отметка в спецификации

\# Как таблица правил и таблица данных связаны с тестами — [Оформление: Таблицы](01-Оформление.md#Таблицы).

| Правило | Как выполнять | Тест |
|---|---|---|
| ИмяПравила | Первая колонка таблицы правил — уникальное в документе имя правила. Полный идентификатор — `<объект>#<имя>`: `Заказ#Оплата`. У таблицы `Тест` вместо имени — заголовок раздела без пробелов: `Заказ#Реквизиты` | `test_дубли` |
| ЗначениеОтметки | Имена тестов через `;`. Пока теста нет — `ТребуетсяТест`, и парсер на нём падает. Пустая ячейка — ошибка | `test_нет_теста` |
| ТестСуществует | Каждый тест из отметки есть в коде | `test_тест_не_найден` |

## Пометка в тесте

| Правило | Как выполнять | Тест |
|---|---|---|
| Пометка | Тест помечается ссылкой на правило с хэшем: `Заказ#Оплата~rvm6djoy`. У теста ровно одна пометка: тест проверяет одно правило. У правила может быть несколько тестов. Правило с таким идентификатором есть в спецификации | `test_правило_не_найдено` |
| ОбратнаяОтметка | Если тест ссылается на правило, его имя есть в отметке этого правила | `test_отметка_забыта` |
| ИмяТеста | Имя теста уникально в проекте | `test_дубли` |
| ВнутреннийТест | Тест без правила спецификации (инфраструктура, внешние сервисы) помечается как внутренний с причиной. Тест без пометки — ошибка | `test_тест_без_спеки` |

## Хэш правила

| Правило | Как выполнять | Тест |
|---|---|---|
| ЧтоХэшируется | Ячейки строки, кроме имени и `Тест`, после нормализации: от ссылки остаётся текст, обратные кавычки убираются, пробелы схлопываются. У строки таблицы решений перед её ячейками идут условия строк над ней: перестановка или вставка строки выше меняет хэш. У таблицы `Тест` хэшируется таблица данных над ней целиком. Выравнивание таблицы и переименование файла хэш не меняют | `test_хэш_устарел` |
| Формат | Ячейки склеиваются через ` \| `; от получившейся строки берётся SHA-256, первые 8 символов base32 в нижнем регистре: `rvm6djoy` | `test_хэш_устарел` |
| Совпадение | Хэш в пометке теста совпадает с хэшем текущей строки правила. При расхождении парсер падает и печатает новый хэш; его вписывают после пересмотра теста | `test_хэш_устарел` |

## Покрытие кода

\# Обратная сторона покрытия правил: непокрытая строка кода — это код без правила или правило без теста.

| Правило | Как выполнять | Тест |
|---|---|---|
| ПорогПокрытия | Прогон тестов падает, если доля строк кода, выполненных тестами, ниже порога. Порог хранится в одном файле проекта и только растёт: если покрытие выросло, порог поднимают в том же изменении | Проверка в CI |

## Пример

\# Тест к строке «Оплата» метода «Оплатить» ([Методы: Пример](04-Методы.md#Пример)). Хэшируется строка «Статус = Оплачен \| — \| Статус := Оплачен; ДатаОплаты := Сейчас \| —»: сначала условие строки выше, затем ячейки самой строки. В Python пометка — декоратор.

```python
@spec("Заказ#Оплата~rvm6djoy")
def test_оплата_заказа(): ...
```

\# Если в эффект строки «Оплата» дописать `; Покупатель.Баллы := Покупатель.Баллы + Сумма / 100`, хэш станет `k2lhh5wh`, и парсер упадёт на правиле «Совпадение», пока тест не пересмотрят.
