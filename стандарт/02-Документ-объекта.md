# Документ объекта

\# Каждый документ спецификации описывает один объект — тип с реквизитами (данные) и методами (поведение). Объект описывается одним документом независимо от числа классов в коде.

## Разделы

| Раздел                   | Что содержит                                                                              | Обязателен           |
| ------------------------ | ----------------------------------------------------------------------------------------- | -------------------- |
| Реквизиты                | Данные объекта ([Типы: Реквизиты](03-Типы.md#Реквизиты))                                  | Да                   |
| Типы и перечисления      | Перечисления и вложенные типы этого объекта ([Типы: Определение типа](03-Типы.md#Определение%20типа)) | Если есть            |
| Методы                   | Поведение объекта, в том числе специальные методы ([Методы](04-Методы.md))                | Если есть поведение  |
| Техническое соответствие | Модуль и хранение ([Техническое соответствие](#Техническое%20соответствие))               | Да                   |

| Правило         | Как выполнять                                                                  | Тест                    |
| --------------- | ------------------------------------------------------------------------------ | ----------------------- |
| ПорядокРазделов | Разделы идут в порядке таблицы выше; обязательные есть всегда, необязательный может отсутствовать; других разделов нет | `test_скелет_документа` |

## Содержание

| Правило | Как выполнять | Тест |
|---|---|---|
| ИмяОбъекта | Заголовок документа — имя объекта по правилу [Имена](01-Оформление.md#Имена): документ `Заказ` описывает объект `Заказ`. От этого имени строится идентификатор правила ([Покрытие тестами: Отметка в спецификации](05-Покрытие-тестами.md#Отметка%20в%20спецификации)) | `test_шапка` |
| ОдинИсточник | Правило записано в одном месте: строка не повторяется дословно в другом разделе или документе | `test_дубли` |
| КодВТехническомРазделе | Вне раздела «Техническое соответствие» нет имён кода (текста в обратных кавычках). Исключение — имена тестов в колонке `Тест` | `test_код_в_техническом_разделе` |

## Техническое соответствие

| Правило | Как выполнять | Тест |
|---|---|---|
| Реализация | Таблица свойств (`Свойство`, `Значение`): `Модуль` — файл кода с классом объекта; `Хранение` — где и как хранится объект, у нехранимого объекта этой строки нет | `test_скелет_документа` |
| ХранениеРеквизитов | У объекта со строкой `Хранение` хранятся все реквизиты: после перезапуска и после выхода новой версии он загружается с теми же значениями. Нехранимое значение — метод или реквизит нехранимого объекта. Переименование, удаление и смена типа хранимого реквизита — только с переносом данных в `ПриОбновлении()` ([Методы: Специальные методы](04-Методы.md#Специальные%20методы)) | `test_миграция_хранения` |
| ТестРеализации | Тест под таблицей свойств раздела проверяет, что класс с именем объекта есть в указанном модуле и что объект сохраняется и загружается без потерь, в том числе данные прежней версии | `test_нет_отметки` |
| ИменаВКоде | Код использует имена спецификации символ в символ, без перевода: объект — класс `Заказ`, реквизит — поле `ДатаОплаты`, метод — `Оплатить`, значение перечисления — `Оплачен`. Парсер находит каждое имя спецификации в коде | `test_имена_в_коде` |
