# Документ объекта

\# Каждый документ спецификации описывает один объект — тип с реквизитами (данные) и методами (поведение). Объект описывается одним документом независимо от числа классов в коде.

## Элементы документа объекта

\# Документ объекта делится на разделы, подразделы и пункты ([Оформление: Элементы документа](01-Оформление.md#Элементы%20документа)). В колонке «Таблица» — шапка единственной таблицы элемента.

| Раздел | Что содержит | Таблица | Подразделы | Обязателен |
|---|---|---|---|---|
| Реквизиты | Данные объекта ([Типы: Реквизиты](03-Типы.md#Реквизиты)) | `Имя \| Описание \| Тип \| Ограничение` | Нет | Да |
| Инварианты | Правила на несколько реквизитов, которые держат данные объекта в согласованном состоянии ([Типы: Ограничения и инварианты](03-Типы.md#Ограничения%20и%20инварианты)) | `Правило \| Условие \| Ошибка` | Нет | Если есть |
| Методы | Поведение объекта, в том числе специальные методы ([Методы](04-Методы.md)) | Нет | Метод | Если есть поведение |
| Типы и перечисления | Перечисления и вложенные типы этого объекта ([Типы: Определение типа](03-Типы.md#Определение%20типа)) | Нет | Перечисление, Вложенный тип | Если есть |
| Техническое соответствие | Модуль, хранение, внешний объект ([Техническое соответствие](#Техническое%20соответствие)) | `Свойство \| Значение` | Нет | Да |

| Подраздел | Заголовок | Что содержит | Таблица | Пункты |
|---|---|---|---|---|
| Метод | Заголовок метода: `Оплатить()` ([Методы: Заголовок метода](04-Методы.md#Заголовок%20метода)) | Поведение метода и входы для тестов | [Таблица решений](04-Методы.md#Таблица%20решений) `Правило \| Условие \| Действия \| Ответ` или [таблица шагов](04-Методы.md#Таблица%20шагов) `Правило \| Шаг \| Условие \| Действия \| Компенсация`; у внешнего объекта таблицы нет | Если есть [примеры](04-Методы.md#Примеры): «Решения» или «Шаги», затем «Примеры» |
| Перечисление | Имя типа: `СтатусЗаказа` ([Типы: Определение типа](03-Типы.md#Определение%20типа)) | Значения типа | `Имя \| Описание`, за ними колонки свойств | Нет |
| Вложенный тип | Имя типа: `ПозицияЗаказа` ([Типы: Определение типа](03-Типы.md#Определение%20типа)) | Реквизиты части объекта и её инварианты | `Имя \| Описание \| Тип \| Ограничение` | Если есть инварианты: «Реквизиты», затем «Инварианты» |

| Пункт | В подразделе | Таблица |
|---|---|---|
| Решения | Метод | Таблица решений `Правило \| Условие \| Действия \| Ответ` |
| Шаги | Метод | Таблица шагов `Правило \| Шаг \| Условие \| Действия \| Компенсация` |
| Примеры | Метод | `Правило \| Реквизиты \| Параметры` |
| Реквизиты | Вложенный тип | `Имя \| Описание \| Тип \| Ограничение` |
| Инварианты | Вложенный тип | `Правило \| Условие \| Ошибка` |

| Правило | Как выполнять | Проверка |
|---|---|---|
| ПорядокРазделов | Разделы идут в порядке таблицы выше; обязательные есть всегда, необязательный может отсутствовать; других разделов нет | Генератор |
| Подразделы | Подразделы есть только у раздела, где они названы в колонке «Подразделы», и только этих видов. До первого подраздела в таком разделе — только комментарий | Генератор |
| ОднаТаблица | В элементе документа объекта — комментарий и либо одна таблица с шапкой из колонки «Таблица», либо вложенные элементы. Другой таблицы и второй таблицы в элементе нет | Генератор |
| Пункты | Пункты есть только у подраздела, у которого две таблицы: у метода с примерами и у вложенного типа с инвариантами. Тогда обе таблицы уходят в пункты из колонки «Пункты», в этом порядке; таблица в самом подразделе не остаётся. Подраздел с одной таблицей держит её без пунктов | Генератор |

## Содержание

| Правило | Как выполнять | Проверка |
|---|---|---|
| ИмяОбъекта | Заголовок документа — имя объекта по правилу [Имена](01-Оформление.md#Имена): документ `Заказ` описывает объект `Заказ`. Из этого имени и имени правила строится имя теста: `test_Заказ_Оплатить_Оплата` | Генератор |
| ОдинИсточник | Правило записано в одном месте: строка не повторяется дословно в другом разделе или документе | Нет |
| КодВТехническомРазделе | Вне раздела «Техническое соответствие» нет имён кода (текста в обратных кавычках) | Нет |

## Техническое соответствие

| Правило | Как выполнять | Проверка |
|---|---|---|
| Реализация | Таблица свойств (`Свойство`, `Значение`): `Модуль` — файл кода с классом объекта; `Хранение` — где и как хранится объект, у нехранимого объекта этой строки нет; `Внешний` — `Да` у внешнего объекта ([Внешний объект](#Внешний%20объект)) | Генератор |
| ХранениеРеквизитов | У объекта со строкой `Хранение` хранятся все реквизиты: после перезапуска и после выхода новой версии он загружается с теми же значениями. Нехранимое значение — метод или реквизит нехранимого объекта. Переименование, удаление и смена типа хранимого реквизита — только с переносом данных в `ПриОбновлении()` ([Методы: Специальные методы](04-Методы.md#Специальные%20методы)) | Нет |
| ТестРеализации | Генератор порождает тест: класс с именем объекта есть в указанном модуле, объект создаётся со всеми реквизитами и читается без потерь | Тесты |
| ИменаВКоде | Код использует имена спецификации символ в символ, без перевода: объект — класс `Заказ`, реквизит — поле `ДатаОплаты`, метод — `Оплатить`, значение перечисления — `Оплачен`. Сгенерированные тесты обращаются к коду по этим именам через тестовую обвязку ([Тесты по спецификации: Тестовая обвязка](05-Тесты-по-спецификации.md#Тестовая%20обвязка)) | Тесты |

## Внешний объект

\# Почтовый сервер, платёжный шлюз, журнал: то, что вызывается из действий, но чьё внутреннее поведение спецификация не описывает.

| Правило | Как выполнять | Проверка |
|---|---|---|
| ВнешнийОбъект | Документ внешнего объекта — обычный документ объекта со строкой `Внешний | Да` в «Техническом соответствии». У его методов есть заголовки по правилу [Методы: Заголовок метода](04-Методы.md#Заголовок%20метода), таблиц поведения нет; реквизитов может не быть | Генератор |
| ВызовВнешнего | Объект обращается к внешнему через реквизит типа `Ссылка."Почта"`: действие `Почта.Отправить(Адрес, «текст»)`. В тесте внешний объект заменяется регистратором, и проверяется, что вызовы были ровно с такими параметрами, в таком порядке | Тесты |
