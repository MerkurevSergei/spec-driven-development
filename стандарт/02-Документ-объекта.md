# Документ объекта

\# Каждый документ спецификации описывает один объект — тип с реквизитами (данные) и методами (поведение). Объект описывается одним документом независимо от числа классов в коде.

## Разделы и подразделы

| Заголовок | Что начинает | Где кончается |
|---|---|---|
| `#` | Документ | В конце файла |
| `##` | Раздел | Перед следующим `##` |
| `###` | Подраздел | Перед следующим `###` или `##` |

| Раздел | Что содержит | Подразделы | Обязателен |
|---|---|---|---|
| Реквизиты и инварианты | Данные объекта и правила, которые держат их согласованное состояние: таблица реквизитов, под ней таблица инвариантов ([Типы: Реквизиты](03-Типы.md#Реквизиты), [Типы: Ограничения и инварианты](03-Типы.md#Ограничения%20и%20инварианты)) | Нет | Да |
| Методы | Поведение объекта, в том числе специальные методы ([Методы](04-Методы.md)) | Метод | Если есть поведение |
| Типы и перечисления | Перечисления и вложенные типы этого объекта ([Типы: Определение типа](03-Типы.md#Определение%20типа)) | Перечисление, Вложенный тип | Если есть |
| Техническое соответствие | Модуль, хранение, внешний объект ([Техническое соответствие](#Техническое%20соответствие)) | Нет | Да |

| Подраздел | Заголовок | Что содержит |
|---|---|---|
| Метод | Заголовок метода: `Оплатить()` ([Методы: Заголовок метода](04-Методы.md#Заголовок%20метода)) | Таблица решений или шагов, под ней примеры |
| Перечисление | Имя типа: `СтатусЗаказа` ([Типы: Определение типа](03-Типы.md#Определение%20типа)) | Значения типа |
| Вложенный тип | Имя типа: `ПозицияЗаказа` ([Типы: Определение типа](03-Типы.md#Определение%20типа)) | Реквизиты части объекта и её инварианты |

| Правило | Как выполнять | Проверка |
|---|---|---|
| ПорядокРазделов | Разделы идут в порядке таблицы выше; обязательные есть всегда, необязательный может отсутствовать; других разделов нет | Генератор |
| Подразделы | Подразделы есть только у раздела, где они названы в колонке «Подразделы», и только этих видов. До первого подраздела в таком разделе — только комментарий. Заголовков `####` и глубже нет | Генератор |

## Содержание

| Правило | Как выполнять | Проверка |
|---|---|---|
| ИмяОбъекта | Заголовок документа — имя объекта по правилу [Имена](01-Оформление.md#Имена): документ `Заказ` описывает объект `Заказ`. Из этого имени и имени правила строится имя теста: `test_Заказ_Оплатить_Оплата` | Генератор |
| ОдинИсточник | Правило записано в одном месте: строка не повторяется дословно в другом разделе или документе | Нет |
| КодВТехническомРазделе | Вне раздела «Техническое соответствие» нет имён кода (текста в обратных кавычках) | Нет |

## Техническое соответствие

| Правило | Как выполнять | Проверка |
|---|---|---|
| Реализация | Таблица свойств (`Свойство`, `Значение`): `Модуль` — файл кода с классом объекта; `Хранение` — где и как хранится объект, у нехранимого объекта этой строки нет; `Внешний` — `Да` у внешнего объекта ([Внешний объект](#Внешний%20объект)) | Генератор |
| ХранениеРеквизитов | У объекта со строкой `Хранение` хранятся все реквизиты: после перезапуска и после выхода новой версии он загружается с теми же значениями. Нехранимое значение — метод или реквизит нехранимого объекта. Переименование, удаление и смена типа хранимого реквизита — только с переносом данных в `ПриОбновлении()` ([Методы: Специальные методы](04-Методы.md#Специальные%20методы)) | Нет |
| ТестРеализации | Генератор порождает тест: класс с именем объекта есть в указанном модуле, объект создаётся со всеми реквизитами и читается без потерь | Тесты |
| ИменаВКоде | Код использует имена спецификации символ в символ, без перевода: объект — класс `Заказ`, реквизит — поле `ДатаОплаты`, метод — `Оплатить`, значение перечисления — `Оплачен`. Сгенерированные тесты обращаются к коду по этим именам через тестовую обвязку ([Тесты по спецификации: Тестовая обвязка](05-Тесты-по-спецификации.md#Тестовая%20обвязка)) | Тесты |

## Внешний объект

\# Почтовый сервер, платёжный шлюз, журнал: то, что вызывается из действий, но чьё внутреннее поведение спецификация не описывает.

| Правило | Как выполнять | Проверка |
|---|---|---|
| ВнешнийОбъект | Документ внешнего объекта — обычный документ объекта со строкой `Внешний | Да` в «Техническом соответствии». У его методов есть заголовки по правилу [Методы: Заголовок метода](04-Методы.md#Заголовок%20метода), таблиц поведения нет; реквизитов может не быть | Генератор |
| ВызовВнешнего | Объект обращается к внешнему через реквизит типа `Ссылка."Почта"`: действие `Почта.Отправить(Адрес, «текст»)`. В тесте внешний объект заменяется регистратором, и проверяется, что вызовы были ровно с такими параметрами, в таком порядке | Тесты |
