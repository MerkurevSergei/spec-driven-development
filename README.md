# Spec-Driven Development

Стандарт простой человекочитаемой спецификации: владелец понимает её без кода, ИИ — однозначно, а тесты по ней порождает генератор, так что расхождение спецификации и кода ловит CI.

## Как это работает

1. Владелец вместе с ИИ пишет документ объекта: реквизиты, перечисления, методы таблицами решений и шагов.
2. ИИ пишет код с теми же именами и один раз — тестовую обвязку: как создать объект и прочитать его.
3. Генератор для каждой строки правила подбирает состояние, исполняет спецификацию и записывает тест. Ожидание берётся из спецификации, поэтому его нельзя подогнать под код.
4. CI перегенерирует тесты при каждом прогоне: зелёный — спецификация и код совпадают.

## Версии

Версии — git-теги `vMAJOR.MINOR.PATCH`. Проект подключает стандарт на конкретном теге и обновляет его осознанно.

| Часть версии | Когда растёт |
|---|---|
| MAJOR | Правило изменено так, что прежние спецификации перестают ему соответствовать |
| MINOR | Новое правило или раздел, прежние спецификации остаются верными |
| PATCH | Уточнение формулировок и примеров без изменения смысла |

До 1.0.0 стандарт ещё складывается: смена MINOR может требовать правок спецификаций, это отмечается в CHANGELOG.
