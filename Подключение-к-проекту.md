# Подключение к проекту

\# Как подключить стандарт и генератор тестов к проекту через git и настроить CI так, чтобы тесты, порождённые по спецификации, проходили вместе с кодом. Примеры — для Python и GitHub Actions; для другого стека меняются только команды и тестовая обвязка. Живой пример — папка [пример](пример/README.md).

## Схема

| Что | Где в проекте | Кто пишет |
|---|---|---|
| Стандарт и генератор | `docs/стандарт-спецификаций/` — git submodule на тег этого репозитория | Не правится в проекте |
| Спецификации | `docs/specs/` — по документу на объект, по правилам стандарта | Владелец вместе с ИИ |
| Предлагаемые изменения | `docs/specs/предлагаемые-изменения/` | Владелец вместе с ИИ |
| Тестовая обвязка | `tests/тест_обвязка.py` — как создать объект, прочитать его, подменить время, сбой и внешние объекты | ИИ, один раз |
| Тесты по спецификации | `tests/test_по_спецификации.py` — порождается генератором при каждом прогоне, не правится и не коммитится | Генератор |
| Порог покрытия | `порог-покрытия.txt` в корне — одно число, процент строк | Только растёт |

## Подключение стандарта

\# Из корня проекта. Адрес — SSH; если CI ходит по HTTPS, используйте `https://github.com/MerkurevSergei/spec-driven-development.git`.

```bash
git submodule add git@github.com:MerkurevSergei/spec-driven-development.git docs/стандарт-спецификаций
git -C docs/стандарт-спецификаций checkout v0.14.0
git add .gitmodules docs/стандарт-спецификаций
git commit -m "docs: стандарт спецификаций v0.14.0"
echo "tests/test_по_спецификации.py" >> .gitignore
```

| Действие | Команда |
|---|---|
| Клонировать проект вместе со стандартом | `git clone --recurse-submodules <адрес проекта>` |
| Подтянуть стандарт в уже склонированный проект | `git submodule update --init` |
| Перейти на новую версию | `git -C docs/стандарт-спецификаций fetch --tags && git -C docs/стандарт-спецификаций checkout v0.14.0`, затем коммит изменения submodule. Перед переходом прочитать [CHANGELOG](CHANGELOG.md) |

\# В AGENTS.md (или CLAUDE.md) проекта добавьте строку: «Спецификации в `docs/specs/` пишутся по стандарту `docs/стандарт-спецификаций/стандарт/00-Обзор.md`; изменил поведение — сначала спецификация, потом код; тесты правил не пишутся, их порождает генератор».

## Генерация тестов

\# Генератор — пакет `генератор` внутри submodule, без зависимостей, Python 3.10+. Он читает `docs/specs/`, для каждой строки правила подбирает состояние, исполняет спецификацию и записывает тест на тестовую обвязку ([Тесты по спецификации](стандарт/05-Тесты-по-спецификации.md)).

```bash
PYTHONPATH=docs/стандарт-спецификаций python -m генератор docs/specs tests/test_по_спецификации.py
python -m unittest discover -s tests -t .
```

| Ситуация | Что происходит |
|---|---|
| Документ не по стандарту | Генерация падает с именем файла, раздела и правила |
| Для строки не подобрать состояние | Генерация падает и называет строку; в документ добавляется таблица [Примеры](стандарт/04-Методы.md#Примеры) |
| Правило не завершается | Генерация падает с текстом «правило не завершается» |
| Код расходится со спецификацией | Падает сгенерированный тест `test_<Объект>_<Метод>_<Правило>`; в его тексте видно, какое состояние и какой результат ожидались |
| Тестовая обвязка не умеет создать объект | Падают все тесты объекта; чинится тестовая обвязка, не тесты |

## CI

\# Пример для GitHub Actions — файл `.github/workflows/tests.yml`. CI зелёный, только когда спецификация, код и порог покрытия совпадают.

```yaml
name: Тесты по спецификации

on:
  pull_request:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: true        # без этого стандарта и генератора в CI не будет
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: Зависимости
        run: pip install -r requirements.txt coverage
      - name: Генерация тестов по спецификации
        run: PYTHONPATH=docs/стандарт-спецификаций python -m генератор docs/specs tests/test_по_спецификации.py
      - name: Тесты
        run: coverage run -m unittest discover -s tests -t .
      - name: Порог покрытия
        run: coverage report --fail-under="$(cat порог-покрытия.txt)"
```

| Ситуация | Что сделать |
|---|---|
| Репозиторий стандарта приватный | Добавьте в проект секрет с ключом доступа на чтение и передайте его в `actions/checkout` (`ssh-key:` или `token:`). Для публичного репозитория ничего не нужно |
| Покрытие выросло | Поднимите число в `порог-покрытия.txt` в том же изменении |
